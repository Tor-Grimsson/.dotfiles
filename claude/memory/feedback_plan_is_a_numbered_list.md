When proposing work, the plan is **a table**. One row per action, columns:
`#` · glyph · the action verb-first with its real path/value · a short description.
Nothing above it — no state table, no context table, no framing paragraph. The table
IS the reply.

Not a numbered list. Not a sentence. Not `1.` items with prose hanging off them —
those still have to be parsed line by line to compare steps. A table lets him scan
one column and see every action at once.

**Why:** 2026-08-01, twice in one session. First a Button icon-ladder proposal
arrived as a dense sentence: *"The plan is a chunky paragraph instead of just listing
sequenced tasks with short description. Maybe use emoji for visual help --
Impossible to understand the plan as a sentence, lists and bullets, make super clear
what actions are being proposed"*. It was re-emitted as a numbered 1–7 list under a
knob-state table, and that failed too: *"its a list 1-7 shoudl be in a table. and
previous table above was uneccesary // still unclear what the plan is, soo much
noise"*. Same failure class as [[feedback_audits_are_tables]]; the correction is that
a plan is parallel facts too, and the surrounding context is the noise.

**How to apply:** Before sending any plan, proposal or recommendation — is it a
table, and is the table the first thing after the lead? If there is a table above it,
delete that table. Glyphs come from the existing ledger vocabulary
(🔵 🟡 🟠 🟢 ⚪ 📌 ⚠ 🔴), never decorative emoji. One plan, one table, one
`Sound good?`.
