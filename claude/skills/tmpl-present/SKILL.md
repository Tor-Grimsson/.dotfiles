# tmpl-present — you present, I confirm

The contract: **understanding first, approval second, build third.** Never fold two of those into one turn.

## Shape

1. **Updated understanding** — what you now believe the ask is, in the user's own terms. Corrections he made get named, not silently absorbed.
2. **Steps to success** — numbered, each one line, in execution order. What each step produces.
3. **Open decisions** — only ones that genuinely change the build; one line each, no surveys.
4. **Stop.** No tool calls after the presentation. No "while I was at it".

## The failure it exists to kill

Creating, naming or renaming something on a "let's name it" / "what should we call it" — an invitation to decide **together** read as authorization to act. Also: presenting a plan and executing it in the same breath, so the review point never happens.

If a name is needed, propose it and stop. The user's word is what makes it real.
